# Manual Testing Scenarios & Best Practices for PINE

## Context
PINE has 558 automated tests across 34 modules, covering the API, the transcription pipeline against mocked models, the ML worker process, the launcher and the edge cases (Tiers 1–3). But many critical user flows — onboarding with real models, real transcription quality, UI interactions, cross-screen state, and above all a clean install — can only be verified by a human. This document is a structured checklist for manual QA.

---

## A. Сценарии ручного тестирования

### 1. Onboarding (свежая установка)

| # | Сценарий | Что проверить |
|---|----------|---------------|
| 1.1 | Первый запуск без моделей | Приложение перенаправляет на `/onboarding`, не показывает главную страницу |
| 1.2 | Определение GPU | Правильно показывает имя GPU + VRAM, или "CPU mode" если GPU нет |
| 1.3 | System check | Python >= 3.8, ffmpeg найден, статус зелёный. Если ffmpeg нет — чёткое сообщение |
| 1.4 | Выбор STT модели | Turbo / Quality переключаются, размер скачивания пересчитывается |
| 1.5 | Ввод HuggingFace токена | Валидный токен — зелёная галочка. Невалидный — ошибка. Пустой — блокирует продолжение |
| 1.6 | Скачивание моделей | Прогресс-бар обновляется. Прерывание интернета — внятная ошибка, не зависание |
| 1.7 | Настройка путей | Кастомный путь для моделей/проектов сохраняется и используется |
| 1.8 | Завершение onboarding | Редирект на главную, модели отмечены как скачанные |

### 2. Управление проектами

| # | Сценарий | Что проверить |
|---|----------|---------------|
| 2.1 | Создать проект | Появляется в списке, папка создана на диске |
| 2.2 | Переименовать проект | Имя обновляется в списке и в шапке. Папка на диске переименована |

| 2.6 | Удалить проект | Удалён из БД и с диска. Подтверждение перед удалением |
| 2.7 | 10+ проектов | Список скроллится, поиск/фильтр работает |
| 2.8 | Одиночные транскрипции | Системный проект "Single Transcriptions" создаётся автоматически |

### 3. Загрузка и транскрипция

| # | Сценарий | Что проверить |
|---|----------|---------------|
| 3.1 | Загрузка MP3 (2-3 мин) | Файл принят, транскрипция стартует автоматически |
| 3.2 | Все 8 форматов | MP3, WAV, M4A, FLAC, OGG, WEBM, MKV, MOV — каждый принят |
| 3.3 | Отклонение .txt / .pdf | 400 ошибка, toast-уведомление |
| 3.4 | Unicode имя файла | `интервью_日本語.mp3` — загружается, имя сохраняется |

### 3a. Мультитрек (Zoom-папка / многоканальный файл)

Дорожка на спикера: диаризация не запускается вообще, pyannote даже не грузится.

| # | Сценарий | Что проверить |
|---|----------|---------------|
| 3a.1 | Папка Zoom с `Audio Record` | Предпросмотр (`inspect-multitrack`) показывает по дорожке на участника до импорта |
| 3a.2 | Имена спикеров из имён файлов | В транскрипте реальные имена, а не «Участник 1» |
| 3a.3 | Файл, где каналы = спикеры | Распознан как мультитрек, каналы разложены по дорожкам |
| 3a.4 | Материал не копируется | Исходная папка остаётся на месте, в проект ничего не скопировано; после переноса/удаления исходника — понятная ошибка, а не тишина |
| 3a.5 | Одновременная речь | Реплики, сказанные внахлёст, обе в транскрипте — не «побеждает» одна |
| 3a.6 | Тишина на чужой дорожке | Whisper не выдумывает текст поверх молчания слушателя |
| 3a.7 | Плеер | Играет микс/исходник, перемотка по клику работает как у обычной записи |
| 3a.8 | Переименование спикера | Работает так же, как в одиночной записи |

## B. Best Practices ручного тестирования

### 1. Подготовка окружения

- **Изолированная среда**: используй чистый `.venv` и пустую БД (`backend/data/pine.db`). Удали БД перед полным прогоном, чтобы начать с onboarding
- **Тестовые аудиофайлы**: подготовь набор заранее:
  - 30-секундный клип (быстрый smoke test)
  - 5-минутное интервью с 2 спикерами (дiaризация)
  - 30+ минут (чанкинг)
  - По одному файлу каждого формата (MP3, WAV, M4A, FLAC, OGG, WEBM, MKV, MOV)
  - Файл с Unicode именем
- **Две конфигурации**: тестируй как с GPU, так и на CPU-only (если есть оба варианта)

### 2. Структура прогона

- **Smoke test (5 мин)**: Onboarding → создать проект → загрузить 30сек клип → дождаться транскрипции → добавить тег → экспорт. Если это проходит — основной flow работает
- **Полный прогон (2-3 ч)**: все сценарии из таблиц выше, по порядку. Ставь галочки
- **Регрессия после изменений**: только затронутые секции + smoke test

### 3. Как фиксировать баги

Для каждого бага записывай:
1. **Шаги** — точная последовательность действий
2. **Ожидание** — что должно было произойти
3. **Реальность** — что произошло (скриншот / лог)
4. **Окружение** — OS, GPU/CPU, размер файла
5. **Воспроизводимость** — всегда / иногда / один раз

### 4. На что обращать внимание

- **Консоль браузера** (F12): держи открытой. Ошибки JS, failed fetch, WebSocket disconnect — всё ценно
- **Серверный лог**: запускай `python backend/run.py` в терминале, следи за tracebacks
- **Toast-уведомления**: success = 2 сек, error = 4 сек. Если toast не появился при ошибке — баг
- **FOUC (вспышка нестилизованного контента)**: при загрузке страницы не должно быть белой вспышки в тёмной теме
- **Состояние после F5**: обнови страницу после каждого действия — данные должны сохраниться
- **Медленные операции**: если что-то > 3 сек — должен быть индикатор загрузки

### 5. Приоритезация

Если время ограничено, тестируй в таком порядке:
1. **Критический путь**: загрузка → транскрипция → теги → экспорт (сценарии 3.1, 3.5, 5.1-5.4, 7.1)
2. **Сохранность данных**: перезапуск приложения, backup/restore (8.7, 9.1, 9.3)
3. **Отмена и ошибки**: отмена транскрипции, отклонение файлов (3.3, 3.6, 3.8)
4. **UI polish**: темы, шрифты, шорткаты (8.1-8.5, 4.4-4.5)
5. **Edge cases**: длинные файлы, много проектов, битые данные (секция 10)
